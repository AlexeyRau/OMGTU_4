## 1. В чём суть работы

### Проблема

Решения в проекте принимаются сразу по нескольким критериям, которые тянут в разные стороны. Пример: облачная LLM лучше понимает команды, но дороже и хуже защищает данные. Как выбрать?

### Идея всех трёх методов

1. Разложить проблему на части (цель, критерии, варианты).
2. Попросить эксперта оценить **каждую малую часть отдельно** (это проще, чем решать всё сразу).
3. Математически собрать оценки в итоговые **веса**.
4. Проверить, что оценки не противоречат друг другу, и посмотреть, как результат зависит от них.

Результат у всех методов одинаковый по форме: числа, дающие в сумме 1. Чем число больше, тем элемент важнее или лучше.

### Три метода: кто на какой вопрос отвечает

| Метод | Вопрос | В нашей работе |
|---|---|---|
| ПАТТЕРН | Что важнее для цели? | какая из трёх задач проекта важнее |
| МАИ (Саати) | Какой вариант лучше? | какой способ использовать LLM |
| Решающие матрицы (Поспелов) | Что надо делать, чтобы достичь целей? | какое фундаментальное исследование нужнее всего |

### Почему именно тема диплома

Преподаватель разрешил заменить стандартные варианты темой диплома. Поэтому:

- в части 1 «общая цель → задачи A, B, C» соответствует цели диплома и его трём главным подсистемам;
- в части 2 решение «какую LLM брать» реальное, оно встаёт перед вами в дипломе;
- в части 3 схема «цели → функции → компоненты → исследования» повторяет структуру проекта.

## 3. Часть 1. ПАТТЕРН

### 3.1. Что это

ПАТТЕРН (от англ. *Planning Assistance Through Technical Evaluation of Relevance Numbers*, «помощь в планировании через техническую оценку чисел относительной важности») — методика, разработанная для планирования больших программ. Она строит **дерево целей** (общая цель, под ней подцели, под ними задачи) и определяет, какие элементы дерева важнее.

Оценка идёт по **трём группам критериев**:

1. **Относительная важность элементов:** что важнее для вышестоящей цели.
2. **Взаимная полезность разработок:** как результаты одной разработки помогают другой.
3. **Состояние и сроки:** насколько мы готовы и как скоро можем внедрить.

### 3.2. Дерево целей в нашей работе

```
Цель: мультиплатформенная система заметок и напоминаний на естественном языке
  ├── A. Понимание намерений (LLM-агент, текст и голос)
  ├── B. Поиск заметок по смыслу (RAG)
  └── C. Напоминания и уведомления
```

### 3.3. Как считается относительная важность

Нужны два набора оценок эксперта:

**1) Веса критериев `q_x`** (сумма = 1). По каким признакам сравниваем задачи?

- K1 — вклад в **удобство для пользователя**, вес 0,60;
- K2 — вклад в **надёжность системы** (не потерять запись, не пропустить напоминание), вес 0,40.

**2) Матрица соответствия `s_jx`** — как эксперт делит «100 %» вклада между задачами A, B, C по каждому критерию:

| Критерий | q | A | B | C |
|---|---|---|---|---|
| K1 (удобство) | 0,60 | 0,50 | 0,30 | 0,20 |
| K2 (надёжность) | 0,40 | 0,15 | 0,30 | 0,55 |

Обоснование: удобство больше всего определяет понимание команд (A получает 0,50), а за надёжность отвечают в первую очередь напоминания, ведь пропущенное напоминание — самый заметный отказ (C получает 0,55).

**Формула:**

```
r_j = Σ_x q_x · s_jx
```

То есть для каждой задачи вклады по критериям складываются с весами критериев.

**Расчёт:**

```
r_A = 0,60·0,50 + 0,40·0,15 = 0,300 + 0,060 = 0,360
r_B = 0,60·0,30 + 0,40·0,30 = 0,180 + 0,120 = 0,300
r_C = 0,60·0,20 + 0,40·0,55 = 0,120 + 0,220 = 0,340
```

**Порядок: A (0,36) > C (0,34) > B (0,30).**

### 3.4. Проверка нормирования (п. 1.4 задания)

Три условия, и их нужно знать наизусть:

1. `Σ q_x = 1` (веса критериев): 0,60 + 0,40 = 1 ✓;
2. `Σ_j s_jx = 1` для каждого критерия (доли делят «целое» на части): 0,50+0,30+0,20 = 1 и 0,15+0,30+0,55 = 1 ✓;
3. `Σ r_j = 1` (итог): 0,36+0,30+0,34 = 1 ✓.

Если первые два условия выполнены, третье выполняется автоматически: `Σ_j r_j = Σ_x q_x · Σ_j s_jx = Σ_x q_x · 1 = 1`. Это хорошее объяснение «почему сходится».

### 3.5. Что значит число `r`

`r_A = 0,36` — это **доля** задачи A в общей важности, а не «оценка по пятибалльной шкале». Важность задач на дереве делится так: 36 %, 30 %, 34 %. Разница между A и C (0,02) небольшая, то есть они почти равноценны.

### 3.6. Что будет при равных весах критериев (п. 1.6)

Меняем `q` на (0,5; 0,5):

```
r_A = 0,5·0,50 + 0,5·0,15 = 0,325
r_B = 0,5·0,30 + 0,5·0,30 = 0,300
r_C = 0,5·0,20 + 0,5·0,55 = 0,375
```

Порядок меняется: **C (0,375) > A (0,325) > B (0,300)**. Первой становится C.

**Вывод:** порядок задач зависит от того, что эксперт считает важнее, удобство или надёжность. Когда веса равны, надёжность (то, где C сильна) перевешивает.

### 3.7. Взаимная полезность (п. 1.7)

Шкала 0–3: 0 — не помогают, 3 — ключевое значение. `M_ij` — насколько разработка **i помогает j**.

| i \ j | A | B | C |
|---|---|---|---|
| A | – | 3 | 3 |
| B | 2 | – | 1 |
| C | 1 | 0 | – |

Объяснение каждой оценки:

- A→B = 3: агент формирует поисковый запрос и извлекает метаданные для RAG; без него поиск по смыслу почти не работает;
- A→C = 3: агент вытаскивает из фразы «напомни завтра в 9» время и повторяемость;
- B→A = 2: найденные заметки дают агенту контекст (например, чтобы обновить существующую запись);
- B→C = 1: поиск слабо влияет на напоминания;
- C→A = 1: уведомления почти не помогают пониманию команд;
- C→B = 0: напоминания никак не помогают поиску.

Суммы по строкам: A = 6, B = 3, C = 1. **A сильнее всех помогает остальным**, это ещё один довод в пользу её приоритета.

### 3.8. Состояние–срок

Эта группа критериев отвечает на вопрос: «Если задача важна, **успеем ли мы её сделать** и сколько осталось?». Для каждой разработки фиксируют текущее состояние, что осталось сделать и срок до внедрения.

Зачем это нужно. Важность сама по себе не решает, что делать в первую очередь. Если важная разработка почти готова, её доводят до результата быстро. Если она далека от готовности и требует много времени, нужно сопоставить выгоду и затраты. А почти готовая разработка средней важности может дать быстрый эффект.

> **Важно:** в таблице состояния и сроков в работе указаны **условные** значения (готовность 60 / 50 / 40 %, сроки 2 / 3 / 3 мес.). Реальное состояние вашего диплома мне неизвестно. Перед сдачей подставьте свои цифры.

## 4. Часть 2. Метод анализа иерархий Саати

### 4.1. Идея

Метод Томаса Саати (МАИ, англ. AHP) решает задачу **выбора лучшего варианта по нескольким критериям**. Главная идея: человеку трудно сразу назвать вес, но легко сказать, «что из двух важнее и насколько». Поэтому все элементы сравнивают **попарно**, а потом из этих сравнений вычисляют веса.

### 4.2. Иерархия

```
Цель: выбрать способ использования LLM в агенте
 ├── K1. Качество понимания намерений
 ├── K2. Стоимость эксплуатации (чем дешевле, тем лучше)
 └── K3. Приватность данных
      Альтернативы: A. Облачный API
                    B. Открытая модель на своём сервере
                    C. Компактная модель на устройстве
```

### 4.3. Шкала Саати

| Значение | Смысл |
|---|---|
| 1 | равная важность |
| 3 | умеренное превосходство |
| 5 | сильное превосходство |
| 7 | очень сильное превосходство |
| 9 | крайнее превосходство |
| 2, 4, 6, 8 | промежуточные |
| обратные (1/3, 1/5…) | предпочтение в обратную сторону |

### 4.4. Матрица парных сравнений критериев

`a_ij` — во сколько раз критерий i важнее критерия j.

|  | K1 | K2 | K3 |
|---|---|---|---|
| K1 | 1 | 3 | 2 |
| K2 | 1/3 | 1 | 1/2 |
| K3 | 1/2 | 2 | 1 |

Как читать: K1 (качество) в 3 раза важнее K2 (стоимости) и в 2 раза важнее K3 (приватности); K3 (приватность) в 2 раза важнее стоимости.

**Принцип заполнения:** диагональ из единиц (критерий равен самому себе), а клетка под диагональю равна **обратному** числу к клетке над ней: `a_ji = 1 / a_ij`. Поэтому эксперт заполняет только верхний треугольник (в 3×3 это 3 сравнения). Это **обратная симметричность** (взаимная обратность).

### 4.5. Веса критериев: геометрическое среднее

**Шаг 1.** Для каждой строки перемножаем числа и извлекаем корень степени n (n = 3):

```
g_K1 = (1·3·2)^(1/3)    = 6^(1/3)    = 1,8171
g_K2 = (1/3·1·1/2)^(1/3)= (1/6)^(1/3)= 0,5503
g_K3 = (1/2·2·1)^(1/3)  = 1^(1/3)    = 1,0000
Σ g = 3,3674
```

**Шаг 2.** Нормируем (делим на сумму), чтобы веса давали 1:

```
w_K1 = 1,8171 / 3,3674 = 0,5396
w_K2 = 0,5503 / 3,3674 = 0,1634
w_K3 = 1,0000 / 3,3674 = 0,2970
```

**Смысл:** качество понимания команд получает 54 % общего веса, приватность 30 %, стоимость 16 %.

**Почему геометрическое среднее.** Точный метод Саати использует главный собственный вектор матрицы. Геометрическое среднее строк — простая и хорошая его замена: для полностью согласованной матрицы результаты совпадают, для почти согласованной отличаются немного.

### 4.6. Проверка согласованности

Эксперт может противоречить себе. Пример: «A лучше B в 3 раза, B лучше C в 3 раза, но A лучше C только в 2 раза», а логично было бы 9. Согласованность измеряет, насколько мнения не противоречат друг другу.

**Формулы:**

```
λ_max = среднее значение (A·w)_i / w_i
CI    = (λ_max − n) / (n − 1)
CR    = CI / RI
```

- `λ_max` у идеально согласованной матрицы равно n; у несогласованной больше n.
- `CI` — индекс согласованности: мера отклонения от идеала.
- `RI` — **случайный индекс**: табличное значение, равное среднему CI у матриц, заполненных случайно. Для n = 3 `RI = 0,58`.
- `CR` — отношение: насколько наша матрица лучше случайной.

**Наши числа (матрица критериев):**

```
λ_max = 3,0092
CI = (3,0092 − 3)/(3 − 1) = 0,0046
CR = 0,0046 / 0,58 = 0,0079
```

**Условие приемлемости: CR < 0,1.** Получили 0,008, то есть суждения согласованы очень хорошо.

*Нюанс на случай глубокого вопроса.* Строгая рекомендация Саати зависит от размера матрицы: порог CR примерно 0,05 для 3×3, 0,08 для 4×4 и 0,10 для больших. В задании указан общий порог 0,1. Наши значения (максимум 0,008) проходят и по строгому порогу.

### 4.7. Матрицы альтернатив (три штуки, по одной на критерий)

**K1. Качество понимания** (облако заметно сильнее, чем открытые модели, а те сильнее компактных):

|  | A | B | C |
|---|---|---|---|
| A | 1 | 3 | 7 |
| B | 1/3 | 1 | 2 |
| C | 1/7 | 1/2 | 1 |

Локальные приоритеты: A = 0,682; B = 0,216; C = 0,103. `CR = 0,0023`.

**K2. Стоимость эксплуатации** (чем дешевле, тем выше приоритет: модель на устройстве почти бесплатна для разработчика, облачный API при небольшой аудитории дешевле собственного GPU-сервера):

|  | A | B | C |
|---|---|---|---|
| A | 1 | 2 | 1/3 |
| B | 1/2 | 1 | 1/5 |
| C | 3 | 5 | 1 |

Локальные приоритеты: A = 0,230; B = 0,122; C = 0,648. `CR = 0,0032`.

**K3. Приватность** (данные остаются на устройстве лучше, чем на своём сервере, и намного лучше, чем у стороннего облака):

|  | A | B | C |
|---|---|---|---|
| A | 1 | 1/4 | 1/7 |
| B | 4 | 1 | 1/2 |
| C | 7 | 2 | 1 |

Локальные приоритеты: A = 0,082; B = 0,315; C = 0,603. `CR = 0,0017`.

Все три матрицы согласованы (CR много меньше 0,1).

**Важная деталь: направление критерия «стоимость».** Мы сравниваем, какая альтернатива **лучше** по критерию, поэтому для стоимости лучше та, которая **дешевле**. Это не «у кого стоимость больше». Если на защите спросят «почему у модели на устройстве такой высокий приоритет по стоимости», ответ: «потому что она дешевле всех в эксплуатации».

### 4.8. Синтез итоговых приоритетов

**Формула:**

```
P_i = Σ_k w_k · p_ik
```

Для каждой альтернативы локальные приоритеты по критериям складываются с весами критериев.

| Критерий | Вес w | p_A | p_B | p_C |
|---|---|---|---|---|
| K1 | 0,540 | 0,682 | 0,216 | 0,103 |
| K2 | 0,163 | 0,230 | 0,122 | 0,648 |
| K3 | 0,297 | 0,082 | 0,315 | 0,603 |
| **Итог P** | | **0,430** | **0,230** | **0,340** |

**Расчёт для A:** `0,540·0,682 + 0,163·0,230 + 0,297·0,082 = 0,368 + 0,038 + 0,024 = 0,430`.

**Победитель: A, облачный API (0,430).** Затем C (0,340) и B (0,230).

**Что означает число 0,430.** Это доля альтернативы A в «общей полезности» (сумма всех P равна 1). Оно относительное: не «43 балла из 100», а «A весит 43 % среди трёх вариантов». Облачный API примерно в 1,26 раза предпочтительнее модели на устройстве (0,430 / 0,340).

### 4.9. Анализ чувствительности

**Зачем:** веса критериев — это мнение, и оно может измениться. Если от небольшого изменения мнения победитель меняется, выбор неустойчив и решать нужно осторожнее.

| Сценарий весов | w1 | w2 | w3 | P_A | P_B | P_C | Победитель |
|---|---|---|---|---|---|---|---|
| базовые | 0,540 | 0,163 | 0,297 | 0,430 | 0,230 | 0,340 | **A** |
| приватность главная | 0,200 | 0,200 | 0,600 | 0,232 | 0,257 | 0,512 | **C** |
| стоимость главная | 0,200 | 0,600 | 0,200 | 0,291 | 0,179 | 0,530 | **C** |
| качество главное | 0,700 | 0,100 | 0,200 | 0,517 | 0,226 | 0,257 | **A** |
| равные веса | 0,333 | 0,333 | 0,333 | 0,331 | 0,218 | 0,451 | **C** |

**Вывод:** облачный API побеждает только если качество понимания остаётся главным критерием. Как только приоритет смещается в сторону приватности, стоимости или равенства, побеждает компактная модель на устройстве. Решение **неустойчиво** к изменению весов.

**Точка перелома по приватности.** Если постепенно увеличивать вес K3 (а остальные два пересчитывать пропорционально), лидер меняется при `w3 ≈ 0,40` (базовое значение 0,297). Как это получается:

```
P_A(w3) = (1 − w3)·0,5766 + w3·0,0823
P_C(w3) = (1 − w3)·0,2294 + w3·0,6026
```

Приравняв, получаем `(1 − w3)·0,3472 = w3·0,5203`, откуда `w3 = 0,400`. Здесь 0,5766 и 0,2294 — «взвешенные средние» локальных приоритетов A и C по критериям K1 и K2, а 0,0823 и 0,6026 — их приоритеты по K3.

**Практический вывод для диплома.** Если вы больше всего цените качество, начинайте с облачного API. Если приватность персональных заметок для вас принципиальна (а для приложения с личными заметками она очень важна), стоит проектировать возможность локального режима. Это обычная гибридная стратегия.

### 4.10. Ограничения МАИ (п. 2.9)

1. **Зависимость от набора критериев и альтернатив.** Что не попало в список, то не учтено. Например, если добавить критерий «задержка ответа» или «поддержка русского языка», результат может измениться.
2. **Рост числа сравнений.** Для n объектов нужно `n(n−1)/2` сравнений в каждой матрице. В 3×3 это 3, в 7×7 уже 21. Кроме матриц критериев нужны матрицы альтернатив для каждого критерия. Растёт нагрузка на эксперта, падает согласованность.
3. **Проблема обращения рангов.** Приоритеты относительны и нормируются на 1. Если добавить в список ещё одну альтернативу (даже копию уже имеющейся) или убрать одну, итоговый порядок остальных может измениться, хотя их свойства не менялись. Это известная критика метода.
4. **Субъективность и дискретная шкала.** Эксперт ограничен значениями 1–9; согласованность проверяет только отсутствие противоречий, а не правильность суждений.

## 5. Часть 3. Метод решающих матриц Поспелова

### 5.1. Идея

Метод используется в **программно-целевом планировании**: когда у проекта есть цели, которым нужны функции, для функций нужны компоненты, а для компонентов нужны исследования. Нужно понять, **на какие исследования направить усилия**, чтобы лучше всего работать на цели.

Приоритеты **передаются сверху вниз** по уровням с помощью матриц.

### 5.2. Четыре уровня

| Уровень | Что это | Элементы в работе |
|---|---|---|
| 0. Цели проекта (направления) | зачем всё это | G1 управление на естественном языке; G2 поиск по смыслу; G3 своевременные напоминания |
| 1. Функции системы (разработки) | что система должна делать | F1 распознавание намерений; F2 сохранение заметок; F3 семантический поиск; F4 планирование и доставка уведомлений; F5 голосовой ввод |
| 2. Программные компоненты (прикладные исследования) | из чего это собирается | K1 LLM-агент; K2 векторное хранилище; K3 планировщик; K4 распознавание речи; K5 клиенты |
| 3. Необходимые исследования (фундаментальные) | что нужно изучить, чтобы компоненты работали | R1 извлечение структуры из текста; R2 векторные представления и поиск; R3 надёжная доставка уведомлений; R4 распознавание русской речи; R5 приватность и безопасность данных с LLM |

### 5.3. Как работает передача приоритетов

**Исходные веса целей** `p(0) = (0,40; 0,35; 0,25)`: управление на естественном языке важнее всего, поиск чуть меньше, напоминания остальное.

**Матрица вкладов B(1)**: строки — функции, столбцы — цели. Число `b_ij` — **какая доля цели j «обеспечивается» функцией i**. Поэтому **сумма в каждом столбце равна 1**: 100 % цели полностью распределяется между функциями.

Пример: цель G2 «поиск по смыслу» распределяется так: F3 (семантический поиск) 0,60, F2 (сохранение) 0,20, F1 (распознавание) 0,15, F5 (голос) 0,05, F4 0,00. Сумма 1,00.

**Формула передачи:**

```
p(1) = B(1) · p(0)        p(2) = B(2) · p(1)        p(3) = B(3) · p(2)
```

То есть вес нижнего элемента равен сумме его вкладов в каждый элемент верхнего уровня, умноженных на вес этого верхнего элемента.

**Пример расчёта F1:**

```
p(1)[F1] = 0,35·0,40 + 0,15·0,35 + 0,25·0,25 = 0,140 + 0,0525 + 0,0625 = 0,255
```

Остальные: F2 = 0,155; F3 = 0,230; F4 = 0,190; F5 = 0,170. Сумма = 1,000.

**Почему сумма всегда 1.** Столбцы B(k) нормированы на 1, а `Σp(k−1) = 1`, поэтому `Σp(k) = Σ_j p(k−1)_j · Σ_i b_ij = Σ_j p(k−1)_j = 1`. Приоритет «не теряется и не появляется» при переходе между уровнями. Это и проверка нормирования (п. 3.6).

### 5.4. Результаты

| Уровень | Вектор приоритетов |
|---|---|
| Направления | G1 0,400; G2 0,350; G3 0,250 |
| Разработки | F1 0,255; F2 0,155; F3 0,230; F4 0,190; F5 0,170 |
| Прикладные исследования (компоненты) | K1 0,294; K2 0,224; K3 0,131; K4 0,153; K5 0,197 |
| Фундаментальные исследования | R1 0,189; **R2 0,207**; R3 0,194; R4 0,160; **R5 0,250** |

### 5.5. Вывод: какая фундаментальная работа важнее всего и почему

**Наибольший вес у R5: «приватность и безопасность данных при работе с LLM» (0,250).** Затем R2 (0,207) и R3 (0,194).

**Почему R5 лидирует.** В матрице B(3) R5 получает вклад сразу от нескольких самых «тяжёлых» компонентов:

```
от LLM-агента K1 (вес 0,2945): 0,40·0,2945 = 0,1178
от клиентов K5 (вес 0,1970): 0,30·0,1970 = 0,0591
от векторного хранилища K2 (вес 0,2243): 0,20·0,2243 = 0,0449
от распознавания речи K4 (вес 0,1530): 0,10·0,1530 = 0,0153
от планировщика K3 (вес 0,1313): 0,10·0,1313 = 0,0131
сумма = 0,2502
```

Объяснение по существу: персональные заметки содержат чувствительные данные, и они проходят через **все** слои системы (агент, хранилище, клиенты). Поэтому вопросы приватности касаются проекта в целом, а не одного модуля. Тогда как, например, R4 (распознавание речи) нужно почти только компоненту K4.

> **Оговорка.** Это следствие моих оценок в матрицах вкладов, которые экспертные. Если вы измените матрицу B(3), результат пересчитается. Метод гарантирует арифметическую верность и согласованную нормировку, но не «правильность» самих оценок.

## 6. Часть 4. Сравнение методов

| Критерий | ПАТТЕРН | МАИ Саати | Решающие матрицы |
|---|---|---|---|
| Основной вопрос | какие задачи важнее для цели | какая альтернатива лучше по критериям | какие работы и исследования нужны для целей |
| Тип матриц | «элементы × критерии» | квадратные матрицы парных сравнений | матрицы вкладов «нижний уровень × верхний» |
| Проверка согласованности | нормировка сумм (Σq = Σs = Σr = 1) | CI и CR (CR < 0,1) | нормировка столбцов (Σ вкладов = 1) |
| Число уровней | 2–3 | 3 и более | 4 |
| Когда применять | структурирование проблемы, приоритеты задач | выбор одного варианта из нескольких | планирование программы разработок и исследований |

**Какой метод лучше подходит для моей задачи.**

- Выбор LLM для агента (конечный набор вариантов, конфликтующие критерии) — это **МАИ**: есть парные сравнения и защита от противоречий.
- Расстановка приоритетов трёх подсистем проекта — **ПАТТЕРН**.
- Планирование исследований под цели диплома — **метод решающих матриц**.

Методы дополняют друг друга: ПАТТЕРН дал структуру задач, МАИ выбрал технологию, Поспелов определил, что исследовать.

## 7. Ответы на контрольные вопросы

**1. Что такое методика ПАТТЕРН? Какие три группы критериев выделяются?**
Это методика структурирования сложной проблемы и определения приоритетов элементов дерева целей. Три группы критериев: (1) относительная важность элементов для вышестоящей цели; (2) взаимная полезность разработок, то есть как одна помогает другой; (3) состояние разработок и сроки реализации, то есть насколько мы готовы к разработке.

**2. Опишите процедуру оценки относительной важности. Как составляется матрица соответствия элементов и критериев?**
Строится дерево целей. Эксперт выбирает критерии и задаёт их веса `q_x` (сумма 1). Затем составляется матрица соответствия: для каждого критерия эксперт делит единицу между элементами (`s_jx`), то есть указывает долю каждого элемента в этом критерии. Относительная важность элемента — `r_j = Σ_x q_x s_jx`.

**3. Какие условия проверяются при нормировании?**
Три: `Σ q_x = 1`; `Σ_j s_jx = 1` для каждого критерия; `Σ_j r_j = 1`.

**4. Смысл коэффициента «состояние–срок». Почему он важен?**
Он учитывает, насколько разработка уже готова и сколько времени остаётся до внедрения. Важность задачи не отвечает на вопрос, стоит ли её делать прямо сейчас: почти готовую разработку можно довести быстро, а дальнюю и затратную нужно соотнести с её пользой. Коэффициент помогает правильно упорядочить реализацию новых проектов и распределить ресурсы.

**5. Сущность метода Саати. Какие этапы включает процесс?**
Метод разбивает задачу на иерархию (цель, критерии, альтернативы), проводит попарные сравнения элементов по шкале 1–9 и вычисляет приоритеты. Этапы: сформулировать цель; определить критерии; перечислить альтернативы; сравнить критерии попарно относительно цели; сравнить альтернативы попарно по каждому критерию; вычислить локальные и итоговые приоритеты; проверить согласованность суждений.

**6. Назначение закона иерархической непрерывности?**
Элементы каждого уровня иерархии сравниваются попарно **только по отношению к элементам соседнего вышестоящего уровня** (и должны быть сопоставимы между собой). Благодаря этому веса передаются от цели вниз: критерии оцениваются по цели, альтернативы по каждому критерию, и итог получается объединением. Для процесса принятия решений это означает, что задача должна быть структурирована как связная иерархия без «пропусков» между уровнями.

**7. Особенности матрицы парных сравнений. Какой принцип при заполнении симметричных клеток?**
Матрица квадратная, на диагонали единицы. Клетки, симметричные относительно диагонали, обратны друг другу: `a_ji = 1/a_ij` (принцип обратной симметричности). Поэтому эксперт заполняет только верхний треугольник.

**8. Шкалы при парных сравнениях.**
Шкала Саати: 1 — равная важность; 3 — умеренное превосходство; 5 — сильное; 7 — очень сильное; 9 — крайнее; 2, 4, 6, 8 — промежуточные; обратные значения при обратном предпочтении.

**9. Порядок расчёта результирующего вектора приоритетов.**
Для каждой матрицы вычисляется вектор весов (через геометрическое среднее строк и нормирование). Затем итоговый приоритет альтернативы получают как сумму произведений веса критерия на локальный приоритет альтернативы по этому критерию: `P_i = Σ_k w_k p_ik`.

**10. Отличие метода решающих матриц от МАИ. Когда применять каждый?**
МАИ выбирает **лучший вариант** из нескольких по критериям на основе парных сравнений с проверкой согласованности. Метод решающих матриц **распределяет приоритеты по уровням** («цели → функции → компоненты → исследования») с помощью матриц вкладов и не использует парные сравнения. МАИ применяют для выбора решения, решающие матрицы — для программно-целевого планирования.

**11. Что такое CI и CR? Условие приемлемости?**
`CI = (λ_max − n)/(n − 1)` — индекс согласованности; `CR = CI/RI` — отношение согласованности (RI — табличный случайный индекс). Согласованность приемлема при `CR < 0,1`.

**12. Что такое анализ чувствительности и зачем он нужен?**
Это проверка того, как меняется результат при изменении исходных данных (весов критериев). Нужен, чтобы понять, устойчиво ли решение: если победитель меняется от небольшого изменения весов, выбор ненадёжен.

**13. В чём проблема обращения рангов в МАИ?**
При добавлении или удалении альтернативы порядок остальных может измениться, хотя их свойства прежние. Причина в том, что приоритеты относительны и нормируются на единицу.

**14. Почему результат экспертной модели зависит не только от оценок, но и от выбранных критериев и их весов?**
Потому что критерии определяют, **по чему** сравниваются варианты: пропущенный критерий или другая формулировка меняет саму постановку. Веса определяют, какой из критериев «перевешивает»: при другом соотношении победит другой вариант, что показал анализ чувствительности.

## 8. Вопросы «на подвох»

**«Откуда вы взяли эти числа?»**
Это экспертные оценки автора диплома, они заданы в ячейках кода и обоснованы смыслом (например, приватность выше стоимости, потому что в заметках личные данные). Метод не создаёт данные, он обрабатывает мнения: ставит их в формальную структуру и проверяет на противоречия. Если оценки поменять, пересчёт делается в один запуск.

**«Раз оценки субъективны, зачем тогда метод?»**
Он делает оценки **явными и проверяемыми**: видно, какое допущение привело к какому выводу. Он проверяет согласованность (CR) и позволяет показать, при каких весах решение меняется (анализ чувствительности). Без метода те же мнения остаются неформализованными.

**«Почему в части 1 два критерия, а в части 2 три?»**
В части 1 оцениваются задачи проекта по двум признакам (удобство и надёжность). В части 2 выбирается технология, и там три критерия, соответствующие реальным компромиссам. Это разные задачи.

**«Почему геометрическое среднее, а не собственный вектор?»**
Для согласованных и почти согласованных матриц результаты практически совпадают, а геометрическое среднее считается проще; именно оно указано в задании.

**«Что делать, если CR оказался больше 0,1?»**
Пересмотреть парные сравнения, найти и исправить противоречащие суждения, потом пересчитать. Согласованность не гарантирует правильность, но большая несогласованность говорит, что мнениям доверять нельзя.

**«Почему у модели на устройстве такой высокий приоритет по стоимости?»**
Потому что мы сравниваем по принципу «чем лучше по критерию, тем выше приоритет», а лучшая стоимость — это меньшая стоимость.

**«Почему вес K1 = 0,54, а не просто 3/6?»**
Из матрицы получается 0,5396 по геометрическому среднему. Матрица не идеально согласована (CR = 0,008), поэтому результат не совпадает с «простыми» дробями. Это нормально.

**«Почему итог МАИ не совпал с результатом ПАТТЕРН?»**
Это разные задачи с разными объектами сравнения: ПАТТЕРН ранжировал подсистемы проекта, МАИ выбирал технологию для агента. Сравнивать их результаты друг с другом нельзя.

**«Почему в части 3 столбцы B суммируются в 1, а не строки?»**
Столбец описывает один элемент верхнего уровня, и его вес полностью распределяется между элементами нижнего (100 %). Строка показывает, от скольких элементов верхнего уровня зависит один элемент нижнего, и её сумма может быть любой.

**«Что бы вы изменили, если бы делали на реальных экспертах?»**
Опросил бы несколько экспертов, усреднил суждения (для парных сравнений обычно берут геометрическое среднее мнений) и проверил бы разброс; уточнил бы критерии; сделал бы анализ чувствительности по всем весам.

**«Какой вывод для диплома?»**
(1) Приоритетная подсистема — агент (понимание намерений). (2) Выбор LLM зависит от приоритета приватности: при высоком приоритете приватности имеет смысл локальный режим или гибридный вариант. (3) Среди исследований первым нужно закрыть вопрос приватности и безопасности данных при работе с LLM.
